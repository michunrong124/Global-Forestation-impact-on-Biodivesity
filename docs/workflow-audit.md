## Checks against the submission files

The submission manuscript governs the documented study design and statistical specification. The audit records the tracked implementation to support verification of the submitted results.

- **Historical snapshots.** The Methods describe majority land cover over five-year windows (1899–1903 for the 1900 baseline, 2016–2020 for the final sample, and centered windows at intermediate dates). The tracked generator begins with seven precomputed TIFFs. Verify the original windowing and tie handling, or provide the exact snapshot TIFFs with provenance.
- **Statistical environment and threshold.** The submission Methods name R 4.3.2 for McNemar tests, while the original repository README reports R 4.5.0 on HPC. Confirm which environment generated the submitted p-values. The Methods specify `p < 0.05 / number of species`. Fig. 3 uses `p <= 0.05 / nrow(table)` for each taxon, mode, and forest-type input table. Use the manuscript comparison as the submission specification. The repository comparison and its per-table denominator are implementation details to verify against the submitted figure outputs before changing the analytical scripts.
- **Table S2.** The submission CSV and repository crosswalk have the same mapping rows. The submission CSV additionally has a blank row and an explanatory footnote about the degraded-forest-to-agroforestry mapping.
- **Code availability.** The submission points to public `main` and says the repository contains the code necessary to replicate the analysis and figures. Reconcile this statement with the input and preprocessing gaps above before release.
